# Processes

These rules extend the Design constraints in `AGENTS.md` for state kept across requests in `src/`, the options `src/cli.ts` passes to `startHttp`, and a review finding that asks for a migration. Several processes may open the same database file at once, and `openDb` in `src/db.ts` turns on WAL and a busy timeout so they can, as the "Database" section of the reference, in `site/src/pages/tools.astro`, says.

- So state that another process also reads or changes (a delivery claim, a session record, a count kept across processes such as a webhook's hourly allowance) is decided in the database inside a transaction, never in one process's memory, as `claimWithin.immediate` in `src/webhooks.ts` does when it claims a delivery and uses its webhook's allowance; a cap on one process's own requests, such as `waiting` in `src/http.ts`, stays in that process's memory.
- A column, format or stored value that exists only in the branch's own commits is in no database made by code on main (a database someone ran an earlier commit of the branch against is not one to migrate): check with `git fetch origin` and then `git grep <exact name> origin/main -- src`, and if it is not there, decline a finding asking for a migration of it, giving that reason.
- Every `serve` runs with `startHttp`'s default for each option `src/cli.ts` does not pass; it passes only `token`, `host`, `port` and `publicUrl`, so `idleTimeoutMs` is always `DEFAULT_IDLE_TIMEOUT_MS`. Code may rely on `serve` using those defaults where a comment at that code says so, as the session sweep comment in `src/http.ts` does ("`serve` always uses the default"). A finding that needs processes to coordinate beyond this, such as revoking a request already running on another process, belongs in a follow-up issue.
